# LEIO Code — MCP dual-era contract (2026-07-28 + 2025-11-25)

LEIO Code is a **dual-era** MCP server. Latest is **2026-07-28** (stateless
`server/discover`, `resultType`, cache hints). **2025-11-25** initialize
handshake stays so current hosts (Grok / Claude / Cursor / SDK 1.30) keep
working.

## MUST / SHOULD we implement

| Spec rule | LEIO behavior |
| --- | --- |
| JSON-RPC 2.0 | SDK transport (stdio + Streamable HTTP) |
| Dual-era: `initialize` (legacy) + `server/discover` (modern) | SDK handshake for 2025-11-25. `installModernProtocol` registers `server/discover` for 2026-07-28 |
| Probes answered before any slow startup work | Tools register pre-connect with permissive kind schemas; the kind catalog loads lazily behind the first `tools/list` / `tools/call` (`installLazyToolAccess`) and upgrades the schemas via registered-tool `update()`. A broken or missing binary degrades to free-form kinds + `kind_catalog_warning` — it never blocks a probe. Diagnostics: `~/.leio-code/mcp-startup-errors.log` |
| `supportedVersions` | `["2026-07-28", "2025-11-25"]` |
| Per-request version negotiation (`-32022` `UnsupportedProtocolVersion`) | Requests declaring an unsupported `_meta["io.modelcontextprotocol/protocolVersion"]` or `MCP-Protocol-Version` HTTP header are rejected with JSON-RPC `-32022` and `data: { supported: ["2026-07-28", "2025-11-25"], requested }` |
| Streamable HTTP header coherence (`-32020` `HeaderMismatch`) | Conflicting `MCP-Protocol-Version` HTTP header vs `_meta["io.modelcontextprotocol/protocolVersion"]` returns HTTP `400` + JSON-RPC `-32020` |
| `resultType` on every result | `finalizeCallToolResult` / discover / list / resource-read wrappers set `"complete"` |
| Result `_meta` carries `io.modelcontextprotocol/protocolVersion` and `serverInfo` | `protocolMeta()` stamps the negotiated protocol version and full `Implementation` metadata (`name`, `title`, `version`, `description`, `websiteUrl`, `icons`) |
| `tools/list` & `resources/list` cache hints (`ttlMs`, `cacheScope`) | Wrapped after registration; 300s / `public` (`server/discover` is 3600s / `public`) |
| `serverInfo` is `Implementation` | `IMPLEMENTATION_STDIO` / `IMPLEMENTATION_APPS_SDK` |
| Servers that expose tools **MUST** declare `capabilities.tools` | Both servers do. `listChanged` is omitted (and SDK auto-assertions on `registerTool`/`update` are suppressed) — we do not emit `notifications/tools/list_changed` |
| Apps widget is a resource; missing resource URIs return `-32602` (`data.uri`) | Apps SDK declares `capabilities.resources`; `resources/read` wraps missing URIs with JSON-RPC `-32602` (`Invalid params`) and `data: { uri }` (SEP-2164) |
| Tool `name` 1–128 of `[A-Za-z0-9._-]` | Asserted at registration; catalog is 19 stdio names |
| Tool `title` + `description` + `inputSchema` | `registerTool` / `registerLeioTool` |
| `outputSchema` optional; `structuredContent` MAY be any JSON | Zod passthrough; summaries/warnings accept objects (audit JSON) |
| `annotations` | Per-tool presets. Clients MUST treat them as untrusted hints |
| Tasks stay out of core | `execution.taskSupport: "forbidden"`. No `io.modelcontextprotocol/tasks` extension |
| Tool execution errors → `CallToolResult.isError: true` | CLI non-zero without envelope, timeouts, spawn failures, input validation throws |
| Protocol errors stay JSON-RPC | Left to the SDK |
| HTTP `MCP-Protocol-Version` | CORS allows the header; SDK Streamable HTTP sets it on 2025-11-25 sessions |

We do **not** implement (and do not advertise): prompts, logging, completions,
sampling, elicitation, roots, MRTR `input_required`, `subscriptions/listen`,
or the tasks extension. The TypeScript SDK in use (1.30) is still handshake-based;
modern clients probe `server/discover` without initialize.

## Error split (do not collapse these)

**Protocol error** (JSON-RPC `error`, model may not see it):

- unknown tool name
- request fails `CallToolRequest` schema
- server/transport crash before a tool handler runs

**Execution error** (`result.isError: true`, model SHOULD see it and retry):

- `leio-code` exit ≠ 0 with no JSON envelope
- timeout / binary missing
- missing `needle` for `explain` / `graph` / `knowledge`
- hosted auth challenge (`auth_required: true`)
- `kb_bootstrap` / `uv` failure

A doctor or audit that exits non-zero **with** an envelope still returns
`structuredContent.ok: false` and `isError: true` so the model can read the
diagnostics.
